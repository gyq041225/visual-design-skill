# 业务设计规范与交互 HTML

目标：保持用户效果图的信息结构、布局和内容，按本规范实现视觉细节，交付实际可操作的 HTML。

## 规范入口

- 基础规范与已知差异：[references/foundations.md](references/foundations.md)。开始实现前读取。
- 组件具体尺寸和状态：在 [references/components-source.json](references/components-source.json) 中按组件名称检索。记录保留 Figma 节点 ID。
- 基础原文：[references/foundations-source.json](references/foundations-source.json)，用于核对文字、颜色、间距等来源。
- 本地 CSS 起点：[assets/tokens.css](assets/tokens.css)。按项目原有 token 系统合并，避免重复全局样式。

## 还原规则

用户本次明确要求优先。效果图决定页面组成与位置，规范决定可对应的颜色、字体、尺寸和状态。遇到明确冲突，列明具体差异；影响整体主题或关键行为时询问，否则记录合理假设后继续。

先检查项目技术栈、现有组件、图标与资源。复用能够准确表达规范的组件，不能仅因规范引用 Arco、Ant 或 M3 就引入整个框架。

设计文件有蓝、绿、紫及备份方案，不混用主题。未指定且效果图不能判定时，以基础总结中的蓝色方案作为暂定主题，并在交付中说明。

输入只有截图时，先识别导航、内容区、表单、表格和浮层；把视觉元素对应到规范组件。不要把截图作为整页背景伪装成 HTML。缺失素材使用明确标记的替代资源，不宣称是原始素材。

需要重新读取 Figma 具体节点时，使用当前环境的 Figma 技能与读取工具。本 Skill 保存的是文字规范及目录快照，不能代替尚未提取的完整组件图层属性。

## 交互与交付

业务要求是可交互 HTML。对页面出现的控件实现合理的演示行为：导航切换、筛选/搜索、排序/分页、表单校验、单选多选、开关、弹窗开闭等，按实际页面范围选择。维护一致的状态与演示数据；不要只在按钮上绑定无关提示。

缺少服务端时使用本地演示数据，并明确说明。持久化只用于有意义的演示场景。未确定单文件或离线要求时，使用项目既有结构；独立交付默认 HTML/CSS/JS 与本地资源包，不自行发布网站。

为适用控件提供 hover、focus-visible、active、selected、disabled、error 状态。用语义化按钮和表单，支持键盘操作；模态弹窗处理焦点进入、Esc 关闭和焦点返回。

在效果图目标尺寸核对布局、字体、留白、颜色、圆角及素材比例；实际运行主要操作，检查控制台错误、溢出与窄屏可用性。交付说明入口文件、可操作范围、演示数据和仍需确认的差异。
